# Day one: a faster local LLM on a Mac Studio M5 Ultra

*2026-11-27. One Mac Studio (M5 Ultra, 96 GB), Ollama with its MLX runner,
Qwen3.8 27B as the daily chat model. Every number below was measured on this
machine today; details and scripts are in the [results log](../README.md).*

We set out to make local chat feel instant, and to cut the time from "send"
to the last word in half. By the end of the day the patched stack runs our
own chats in production.

## What changed

| | Before | After |
|---|---|---|
| Writing speed (average of prose, code, chat) | 100 tok/s | **129 tok/s** |
| First word on a chat follow-up, 10k–70k tokens | 0.7–4.2 s | **0.12–0.25 s** |
| First word on a follow-up at 139k tokens | 12.5 s | **0.46 s** |
| First word in a new chat (6.4k-token system prompt) | 3.7 s | **0.2 s** |
| My chat while 3 batch jobs run | 49 tok/s | **100 tok/s** |
| 8 chats at once, total | 168 tok/s | **265 tok/s** |

## The biggest win was not speed

Qwen3.8 is a hybrid model: most layers keep a recurrent state that cannot be
rewound. Ollama saves that state only every 8,192 tokens. Our chat client
moves a date stamp off the previous message on each turn, so every follow-up
differed from the cache inside the last turn and re-read up to 8k tokens.
Saving the state at the start of each chat turn fixed it: follow-ups went
from seconds to a fifth of a second. We filed it upstream as
[ollama#19952](https://github.com/ollama/ollama/issues/19952).

## The rest

- **Uniform 4-bit weights** beat the official mixed builds: +18% to +29%
  decode on Qwen3.8 27B, +14% on Gemma 4 31B, +22% on Qwen3.6 35B-A3B.
  Verifying 2–4 draft tokens is cheaper in affine int4 than in nvfp4 on this GPU.
- **Two open Ollama PRs, tested on M5 Ultra:** batched draft proposals
  (#19769, +58% total at 8 clients) and a disk cache of conversations
  (#19745). The disk cache wrote 2.2 GB per chat turn, so we made it write only
  when a conversation goes idle: 11 GB of disk traffic over 5 turns became 7 MB.
- **Priority tiers:** batch work pauses while the owner's chat runs (and,
  later, voice). A tier is honored only with a key, so no caller can promote
  itself.

## What did not work

- A smaller draft vocabulary (+5% on one draft type, −3% on the other),
  retraining the draft head on the model's own answers (no gain), a second
  draft branch (about +4%, not worth it), and the fast recipe on an
  abliterated model (slower).
- **+50% decode on prose and chat is out of reach with today's drafts.** Each
  guessed token is right 60–75% of the time, which caps a round near 3.3
  tokens; +50% needs about 3.8. Code is already there.
